Today: eight agents on one audio channel, seven loops
Layer 1
Ingest
synthetic events, 10 Hz ball
Match engine streams passes, shots, tackles, pressure and ball samples on a real-time clock. Spotter turns events into moments worth saying. code
Event loop: one Agent Framework workflow per event; Pub/Sub-free, in-process, <5 ms. Runs all day on Container Apps; the clock is the engine's, not the browser's.
Layer 2
Interpret
stats, patterns, context
Caller writes play-by-play from reviewed sentences in four languages. StatWatcher reports the one stat you follow (shot speed, pass length, press height). code
Stat loop: every event recomputes possession, pass length, shot speed, press height from the raw events; nothing is stored that the events cannot rebuild.
Layer 3
Explain
why a moment matters
Analyst reads the match through tools during stoppages and returns structured claims (metric, before, after); causes are graded against a hidden truth log and never spoken. gpt-5.4-mini on Foundry
Stoppage loop: one workflow per stoppage of 15 s or more; paced by a token budget; no Analyst call while nobody listens. 2,322 windows graded on 40 held-out matches.
Layer 4
Verify
the model proposes, code decides
Checker recomputes every claim and every number. Auditor re-reads each line on its own code path against templates, roster and event log. code
Verification loop: 63,430 wrong names and numbers planted on 40 unseen matches, all blocked, none false. A line that fails airs as nothing, never as a guess.
Layer 5
Arbitrate and render
one serial audio channel
Director decides who has the floor, cuts small lines when a goal goes in, keeps never-drop lines with an "earlier" marker. Voice picks the Azure HD neural voice and the ear. Recap at half and full time. code
Air loop: the Director ticks with the clock; audio is synthesised once per unique line and cached; the ball is placed in sound between the ears; 97-98% of shots and cards spoken within 3 s at 30 listeners (post-freeze).
Layer 6
Personalise
one match, many listeners
Casual or Analyst mode, four languages, follow one stat, app voice or screen reader, one ear or both. The same intelligence reaches a data-hungry analyst and a casual fan as different experiences. listener chooses
Group loop: one Director per language × mode × output; groups capped at 64 and pruned after 45 s idle; lines shared across groups when the SSML is the same.
Layer 7
Govern and learn
spend, safety, evidence
Monitor alerts fire an Automation runbook that switches the AI off; the app falls back to cached audio by itself. Entra managed identities, no keys. Pre-registered evaluation with a hidden truth log. code budget: Carson
Guard loop (alerts, hourly and daily) and evaluation loop (tag, run of record, publish whichever way it goes). The number that decided a feature: causes right 1 in 10 vs 1 in 4 for a rule, so causes do not air.
Next: the same loops on real feeds, with memory and more agents
Weeks 1 to 4 after the hackathon
Real event feeds and streamed audio
  • Replace the engine with a licensed live feed (StatsBomb, Opta or the Premier League's own) behind the same Ingest contract; the engine stays as the test double.
  • Streamed speech: Azure AI Speech returns compressed audio as it synthesises; the client starts playing on the first chunk. Flagged build measured against today's load test.
  • Listening test with blind testers (protocol earshot-listening-v1, pre-registered), then fix what they say.
Months 2 to 3
Auto-eventing from video, more agents
  • Vision agent on the broadcast feed (Azure AI Vision + Foundry) to generate passes, shots and speeds without hand tagging, checked against the feed where both exist.
  • Scout agent: favourite club and player focus; a Player agent that follows one player through the match.
  • Agents published as A2A cards in Foundry's Agent Registry; MCP server already exposes the match tools to other agents.
Months 3 to 6
Memory and personal context
  • Foundry Memory Bank per listener: the clubs you follow, the stats you ask for, the pace you prefer; lines adapt without the listener resetting anything.
  • Accounts, notifications and support (decisions in PRODUCT.md); offline-first caching of recaps on the phone.
  • Studio mode: recaps and the agent trail as data for broadcasters, over the same MCP tools.
Scale
Many matches, many languages
  • One Container Apps job per match, fanned out by Azure Service Bus; Web PubSub for tens of thousands of listeners; Azure Front Door and a Speech endpoint per region so the first sound stays under 2 s everywhere.
  • Microsoft Fabric as the stats lakehouse across seasons; the evaluation harness runs nightly on every match and publishes its own error rate.
  • Languages added by writing the sentence set and picking two HD voices; the pipeline does not change.
What stays fixed
The rules that do not change
  • Every number a listener hears is computed by code and checked twice. The model explains; it never asserts a fact it did not read from the data.
  • A listener who cannot check what they are told is never told something wrong: a failed check airs as silence, not a guess.
Blue bars: the loop that runs each layer. Grey pills: deterministic code. Blue pills: the model. Red pills: a person.
