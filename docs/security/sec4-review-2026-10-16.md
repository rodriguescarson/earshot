## Checked and fine
- **`/audio/{name}`:** names must be 24 alphanumerics plus `.m4a`, so no path traversal. No SSRF anywhere: no endpoint fetches a caller-supplied URL.
- **Judge codes:**
  - only SHA-256 hashes are stored, compared in constant time;
  - `/api/ticket` and `/api/metrics` allow 10 tries a minute per IP;
  - tickets are HMAC-SHA256 over a per-process key, with expiry checked.
- **Negotiate:**
  - tokens are receive-only (`webpubsub.joinLeaveGroup.<group>`) and last at most 60 minutes;
  - the group name is validated;
  - cached-only mode answers 503.
- **MCP:** read-only tools, input regexes, 10 a minute anonymous and 60 with a judge code, answers bounded by match time (leakage test in `tests/test_mcp.py`).
- **Infrastructure:**
  - every resource is keyless: Web PubSub and AI `disableLocalAuth`, Storage `allowSharedKeyAccess=false`, App Insights Entra-only ingestion;
  - user-assigned identities have RBAC scoped to containers;
  - no app identity can read `hidden`.
- **Image:** runs as uid 10001; no secrets; the build asserts no `data/hidden`.
- **CI/CD:**
  - deploy uses GitHub OIDC with the subject restricted to `repo:rodriguescarson/earshot:ref:refs/heads/main`;
  - the deploy identity holds Contributor on the registry only (for `az acr build`) and Container Apps Contributor on `rg-earshot`;
  - CI runs gitleaks and `pip-audit`.

## Open, low, by design or for a decision
- `/api/status` publishes the day's spend counters. They are not sensitive, but they are visible.
- `/audio/*` has no rate limit (files are about 50 KB; egress is the only cost).
- Negotiate issues Web PubSub tokens for groups the live app only creates for SSE listeners. Today a Web PubSub-only client would receive nothing. This is a functional gap, not a vulnerability. The client uses SSE.
