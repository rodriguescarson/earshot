## Problem Statement

Blind and partially sighted football fans get live description only where a human describer or
stadium hardware happens to be:
- **Broadcaster audio description:** a UK broadcaster announced it on 2026-10-08 for about 109 of
  380 league games (one match per gameweek day, from 10 October). Source checked 2026-10-16:
  Broadband TV News, 2026-10-08, and SVG Europe. "In English" is our inference, not stated there.
- **The 2026 World Cup:** FIFA offered human description in two languages per host country, plus
  haptic boards at select matches.
- **Haptic tablets** (Touch2See, Field of Vision) exist only in the stadiums that buy them.

Earshot is a solo entry to the Microsoft x Premier League "Inside the Game" hackathon. AI agents turn
a synthetic match's event stream into live audio-described commentary on the fan's phone. It is in
the listener's language, follows their club and player, and places the ball in sound.

Every name and number a listener hears is checked against the match data. Explanations are
built from a fixed set of checkable claims, and their accuracy is graded offline (see Line Safety).

The same moment stream exports timed overlay cues and a described-audio track for broadcasters.
The submission deadline is 2026-10-27 23:59 PT.

## What Makes This Cool

You can close your eyes and hear where the play is:
- a continuous ball tone, placed left to right along the pitch
- a crowd sound that swells as an attack gets dangerous
- speech that only has to say who and why

The safety argument is the insight. Most of a description is *who, where, what*, and code produces
that exactly from event data. The model only explains *why*, only in dead-ball pauses, and only
through claims that code can check. Generic AI commentary puts the model on the facts, which is the
wrong way round for a listener who cannot check what they're told.

### Event contract
- SPADL action types, extended with explicit stoppage events. `stoppage_start` names the restart,
  and dead time is modelled per stoppage type.
- Each event carries `clock_ms` and `wall_ms`.
- Positions use a fixed broadcast frame: x runs 0–105 m, left to right as the main camera sees it.
- xT is fitted and evaluated in an attacking-direction frame, converted from the broadcast frame
  using each team's direction per half.

### Runtime split
- **Shared server pipeline, one per match.** One Agent Framework workflow, and its agents are
  listener-neutral:
  - **Spotter:** finds moments and gives each a neutral priority, a deadline and club tags.
  - **Caller:** per-language templates.
  - **Analyst:** one call per dead-ball window of 15 s or more (about 25 a match), returning up
    to 3 ranked claims per club (amended by the CEO review; the Director caps what airs per mode).
  - **Checker:** validates every line.
  - **Voice:** builds SSML per language, then runs TTS, cached per unique `{text, language, voice,
    pan bucket}` with pan quantised into 5 buckets.
  
  Its output is a line queue for each `{match, language, listening_mode}`: Casual and Analyst use
  separate template sets.
- **Per-listener selection.** The server-side Director executor applies every per-listener rule:
  club and player boosts, the order of the clubs' claims, listening mode (Casual or Analyst), output mode, followed stat. It decides what airs and when: preempt flags, stale drops,
  never-drop rules. It publishes to a Web PubSub group keyed `{match, language, listening_mode, output_mode,
  club, player, stat}`.
- **Client mixer.** The client carries out the Director's instructions. It stops the current clip
  when a `preempt` line arrives, ducks the continuous layer under speech, and synthesizes the
  continuous layer locally from a 10 Hz `ball` stream.
- **Web PubSub messages:**
  - `line {id, priority, preempt, never_drop, audio_url, text, ssml_hash, deadline_ms}`
  - `ball {clock_ms, x, y, danger}`
  - `state {score, clock_ms, period}`

### Line Safety
- **Claims, not free text.** The Analyst may only emit claims from a fixed list:
  - a metric changed (press height, tempo, directness, width, line height, possession share, shot
    count) over a stated window, in a stated direction
  - a cause label from the closed vocabulary (`PRESS_HIGHER`, `DROP_DEEPER`, `GO_DIRECT`, …)

  The Analyst outputs only structured JSON: claim type, parameters, direction, cause label and
  cited event ids. **It writes no sentences.** Every sentence comes from a fixed template for its
  claim type and direction. Each template has a "why it matters" variant and is written and
  reviewed offline in each language, including the agreement variants.
- **What the Checker verifies live:**
  - every name and number comes from a slot
  - each metric claim's value and direction match code-computed statistics over the cited window
  - cited events exist

  The **cause label is not verifiable live.** It is graded offline against the hidden truth log,
  and that accuracy is a reported result (see Success Criteria). Anything outside the claim list
  is rejected.
- **Allowed values:** values in the event log, plus values derived from it by named code
  functions (score, minute, counts, metric values).
- **Translation happens offline, never at runtime.**
  - Caller and claim templates are drafted per language with model help, then back-translated and
    spot-checked. A native speaker reviews them where one can be found; otherwise that is stated
    as a limit.
  - At runtime, the Checker and the auditor verify each aired line by exact match against the
    template-plus-slot rendering. That also catches any name that did not come from a slot.
  - Names fill from per-language roster tables. Each table is produced offline by transliteration
    plus a model pass, then spot-checked: 20 names per script.
  - Numbers and scores are rendered by code into SSML: `say-as` cardinal or ordinal, scores as
    explicit per-language words.
  - Agreement around slot values (Arabic number and gender agreement, Spanish gender) is handled
    by per-language template variants, not by free text.
- **Final Checker pass on the exact SSML sent to Speech.** Anything numeric that didn't come from a
  slot blocks the line. That covers digits in ASCII, Arabic-Indic, Eastern Arabic-Indic and
  Devanagari, plus per-language lists of number words and ordinals.
- **Independent audit.** A separate auditor (a different code path) re-parses every aired SSML
  line against the event log and the derived functions. Facts are measured by the auditor, not
  the Checker.
- **Planted-defect control.** Defects are injected at a known rate at four points in the runtime
  pipeline:
  - Analyst JSON: fabricated parameters, wrong direction, event ids that don't exist or fall
    outside the window.
  - Slot values: out-of-set values, and real-but-wrong values such as the other club's score.
  - Roster table entries: a wrong name for a player id.
  - Template strings: a stray numeral or name in template text.

  The Checker's recall and false-block rate are reported per injection point. Real-but-wrong slot
  values pass the Checker's set-membership test by design, so they are named as the auditor's job:
  it recomputes each slot from the claim parameters, and its recall on them is reported separately.
- **Fallbacks.** Every one is logged to the producer view.

| Failure | What the listener hears |
|---|---|
| Analyst claim rejected (not on the list, or fails the metric check) | dropped, replaced by the code stat line for its metric if one exists |
| Rendered line fails the exact-match or SSML check | dropped, replaced by the code stat line in that language |
| Analyst timeout | code template "window summary" line |
| TTS failure | pre-rendered fragment line; if that fails too, the live region (text) |
| Caller line | never blocked live (templates); audited only |

- **Never-drop invariant.** Goals, red cards and penalties awarded are never dropped as stale and
  never lost to a block. If late, they air through a code template with an "earlier" marker.

### Listening modes and controls
- **Setup, one decision per screen:** (1) language; (2) how Earshot should talk to you: Earshot's
  voice with sound (default), through my screen reader (text only), or one ear only; (3) listening
  mode, Casual or Analyst, with (3b) "Follow one stat?" only after Analyst; (4) club and player,
  skippable; (5) Listen.
  - A "How Earshot talks" control on the listening screen changes mode 2 later (renamed from "Sound settings" by DR-7).
  - Wireframe updated:
    `/var/folders/jb/5w0vp0dj7vv45mkdsjfqhd3w0000gn/T/gstack-sketch.dqgJuX/sketch.png`
    (temporary; it gets copied into the repo at scaffold). Persistent copy from the design review:
    `~/.gstack/projects/inside-the-game/designs/wireframe-20261014/sketch.png` (and `sketch.html`).
- **App voice mode:**
  - Speech clips play through `<audio>` with the Media Session API. Speech pan is capped at ±0.6,
    so the far-side ear still hears.
  - The continuous layer runs on Web Audio.
  - Commentary ducks on the app's own interaction events (`focusin`, touch, key). A web page cannot
    observe VoiceOver's cursor, so VoiceOver's own speech relies on the iOS VoiceOver Audio Ducking
    setting. The iPhone test verifies both.
- **One-ear mode:** speech pan off (centred). The continuous tone plays in mono, with a pitch
  earcon for the pitch third. Position words ("left wing") stay in the speech.
- **My screen reader mode:**
  - At most 8 lines a minute: goals, red and yellow cards, shots, dangerous attacks, restarts, and
    Analyst lines at dead balls.
  - One polite live region whose text is replaced, not appended, so the queue can't pile up.
    Goals and red cards go to an assertive region.
  - The Director applies staleness before writing, since a queued line can't be withdrawn.
  - The continuous layer is off by default, with a toggle.
- **"Where's the ball?"** A code template built from the latest ball position and possession, and
  Checker-covered. It preempts play-by-play but yields to goals, shots and red cards, which cut it off.
- **"Catch me up".** A code-generated recap from the event log: score, time, the last 5 key events.
  It's templated, not the Analyst. Same priority as "Where's the ball?".
- **Listening mode** (replaces the detail toggle; CEO-1). Casual or Analyst, defined under
  "Amendments from the CEO review". On resume after Pause, playback jumps to live and plays
  "Catch me up" first.
- **Personalization rules,** all applied in the Director:
  - **Followed club:** that club's attacking moments get a priority boost and win ties, and that
    club's claim airs first in a window.
  - **Followed player:** each of their touches is eligible for a line. They also get speed tags
    when a threshold is hit. The tags come from SPADL carry events and the ball path, labelled
    "with the ball" (carry speed and carry distance). There are no total-distance claims.
    Off-ball distance stays out of scope (frames exist only for the render match); this mode
    announces touches, carries with speed, passes, shots and duels.
  - **Skipped:** neutral priorities.
  - **Claim airing rule** (per-mode caps under "Amendments from the CEO review"). Claims air as
    separate lines, each at most 6 s. Order:
    - the followed club's claim first;
    - with no followed club, the claim with the larger metric change, measured as a multiple of
      its threshold, goes first.
    
    A second claim still queued when play restarts is dropped as stale and logged to the
    producer view.

### Synthetic engine
- **Growth:** it grows from a thin slice to the full season. The slice is events, ball path and
  stoppages over 40 seeded matches. The hidden tactical truth log and the baseline detector are
  added to the slice on Oct 16–17. The full season (380 matches) is grown on Oct 20–21.
- **Uses of the truth log:** it grades the Analyst's cause labels against the baseline detector.
  This works on the 40-match slice too, so grading survives cutting the full season, and G4 and G5
  apply on 40 matches.
- **Held-out evaluation set.** The development slice uses seeds 1–40. Before any evaluation
  match is generated, these are frozen and git-tagged `eval-freeze`:
  - the Analyst prompt
  - the claim templates
  - the xT fit
  - the baseline detector

  The Explanations result is graded only on 40 fresh-seed matches (seeds 9001–9040) with truth
  logs, never on the development slice. That is true on every path, including if the full season is cut.
- **Danger signal:**
  - Oct 18–19 listening test: xT fitted on the 40-match slice.
  - Shipped build: xT refitted on the full season. The largest cell change is reported next to
    the test result.

### Judge playback model
- **Default:** the judge link starts a 3-minute action-dense clip on demand from the beginning.
  Clips are chosen by Spotter density from the season. Audio is pre-rendered per profile group and
  cached, so repeat listens cost almost nothing.
- **Full match:** a full-match 1× replay is available as a second, quieter link.
  - It is pre-rendered for each language with default settings (App voice, Casual listening mode,
    no followed club or stat).
  - Other profiles generate live.
- **Hosting:** all pre-rendered clips and replays sit on a Blob static website, separate from the
  Container App, so they keep working if the app is degraded.
- **Comparison:** the optional comparison runs on clips, with the same three arms as the listening
  test, and is reported as descriptive only.

### Azure
- **First:** Container Apps, Web PubSub, Foundry, Speech, App Insights, Blob storage.
  - Foundry has two models: the Analyst model (claim selection) and a small judge model for
    Foundry evaluations. Template drafting uses models at dev time only.
  - Blob storage: audio cache, season outputs, audit logs.
- **Then:** Event Hubs (match event ingest) and Cosmos DB (match state and aired-line audit).
  - They are on the cut list (CEO-9, "Event Hubs and Cosmos").
  - The p95 latency is measured with them in the path. If either breaks the 2.0 s budget, it is
    reverted to the in-process queue plus Blob audit.
- **Infra:** Bicep with `azd`, and a GitHub Actions OIDC deploy.

### Cost and abuse controls
- **Estimates:** superseded by the cost lines under "Amendments from the CEO review", which split
  per-match pipeline cost from per-listener cost.
- **Real-time guards** (these are the actual protection):
  - Live sessions: at most 3 concurrent per IP and 150 minutes a day.
  - Caps on Analyst tokens per day and TTS characters per hour.
  - Pre-rendered clips and replays are exempt from both limits.
  - Judges get an access code in the submission's testing instructions that bypasses the per-IP
    limits, since a judging panel may share one corporate IP.
- **Budget backstop:** an Azure budget with alerts at 50% and 90% of $150. It lags usage by hours,
  so it degrades rather than kills.
  - Its action group triggers a Function that switches the app to cached-only mode: live Analyst
    and TTS generation off, pre-rendered clips and replays still served from the Blob static site.
  - Judges see a one-line notice.
  - Carson gets an alert and restores live mode by hand.

### Compliance
- **Names:** every generated list (clubs, players, coaches, referees, stadiums) is checked against
  - the GeoNames cities and places list (CC BY), and
  - a list of real professional footballers pulled from Wikidata.
  
  Neither list is redistributed; they're used only as filters.
- **Audio:** crowd and earcon audio are synthesized procedurally, with no samples.
- **Before the repo goes public:** gitleaks plus a banned-names scan across the full history, and
  a check of every committed image.

## Success Criteria

Pre-register these in `EVALUATION.md` before each run, and report misses as results.

- **Submission:** submitted by Oct 28 12:29 IST, with all required items and a live link.
- **Listening test.** The protocol is set in advance:
  - **Arms:** speech-only, speech + pan, speech + pan + continuous.
  - **Design:** within-subject, with counterbalanced arm order and three clips matched for action
    density.
  - **Questions:** score, who has the ball, and where.
  - **Setup:** stereo headphones with a left/right check at the start; n stated.
  - The result is reported whichever way it goes.
- **Never-drop:** 100% of goals, red cards and penalties aired, with their latency distribution
  reported.
- **Coverage:** at least 95% of shots and yellow cards described within 3.0 s.
  - Method: the full 380-match season runs on an accelerated clock. TTS and Analyst latency are
    drawn from the distribution measured in the deployed load test, and the Checker, Director and
    auditor are real.
  - Real Analyst calls run on a stratified 40-match sample, where cause labels are graded against
    the truth log.
  - Under Approach A+ (or if the full season is cut), the same criteria apply on 40 matches.
- **Facts:** the independent auditor finds zero aired lines with a name or number outside the
  allowed set, in any language. The planted-defect recall and false-block rate are reported.
- **Explanations:** cause-label accuracy against the truth log, on the held-out matches (seeds
  9001–9040), is reported next to the required baseline detector's accuracy on the same matches.
- **Latency:** p95 from event to first audio byte under 2.0 s on the deployed stack, with the load
  N stated against the Speech quota.
- **Device:** iPhone + VoiceOver lock-screen behaviour, in both modes, tested and documented.
  Android with TalkBack gets a smoke check only, stated as such.
- **Blind testers:** at least one session if possible, reported honestly, including "none".

### Section 4: Data Flow & Interaction Edge Cases

```
 EVENT -> SPOTTER (validate ids, clock monotonic) -> CALLER/STATWATCHER (template + slots) -> CHECKER -> VOICE (SSML, TTS) -> QUEUE -> DIRECTOR -> PUBSUB -> CLIENT
   nil/missing id ......... slot fails -> blocked + logged (never a blank name)
   empty window ........... window-summary line or silence-by-design (heartbeat keeps the watchdog quiet)
   wrong type/out of set .. Checker blocks -> stat line fallback
   TTS timeout/429 ........ fragment line -> live region (+ CEO-10 notice if playback fails)
   duplicate event id ..... Spotter drops duplicates by event id (owner must prove idempotence)
   stale (> deadline) ..... dropped, unless never_drop -> late template "earlier"
   encoding (ar/hi) ....... SSML final pass on exact bytes; Devanagari/Arabic-Indic digit scan
```

**Async ordering.** Invariant: a never-drop line always airs, possibly late, and on-demand lines never delay it.
- The Director runs one priority queue per group. The client mixer obeys `preempt`.
- **Order 1:** a goal arrives while "Catch me up" is airing. The goal line carries `preempt`, so the recap is cut and the goal airs. Holds.
- **Order 2:** "Catch me up" is requested while the goal line is airing. The request queues behind the higher-priority goal line. Holds.
- **Order 3:** StatWatcher and Caller lines carry the same `clock_ms`. Priority order applies, then event id as a stable tiebreak. Holds.
- The mechanism is one priority queue per group, and the client never re-orders.
- *Regression proof:* a Director test with controlled release points covering both orders of goal vs on-demand, and goal vs Analyst.
